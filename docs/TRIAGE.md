# 🤖 Shifa+ — محرك الفرز الذكي (TriageAI)

> `services/TriageAI.php` — 525 سطر

---

## نظرة عامة

محرك الفرز الذكي في شفاء+ يُنفّذ مهمتين مستقلتين:

1. **التصنيف** (`classify`) — تصنيف الأعراض إلى أولوية طبية + تخصص مناسب
2. **الجدولة** (`scheduleWithAI`) — اختيار أفضل موعد مع إزاحة تسلسلية

كلتا المهمتين تعملان عبر AI أولاً، مع fallback محلي في حالة الفشل.

## 🔄 خط سير الفرز (Pipeline)

```
الأعراض + شدة الألم + المدة + الأمراض المزمنة
                    │
                    ▼
    ┌─────────────────────────────┐
    │     هل المريض يطلب طوارئ؟   │
    └────────┬──────────┬─────────┘
             │ نعم      │ لا
             ▼          ▼
    ┌──────────┐  ┌──────────────────────┐
    │ Critical │  │ إرسال للـ AI Provider │
    │ فوري     │  │ (Groq → Gemini →     │
    └──────────┘  │  OpenAI)             │
                  └──────────┬───────────┘
                             │
                    ┌────────┤ فشل؟
                    ▼        ▼
           ┌──────────┐  ┌─────────────────┐
           │ نتيجة AI │  │ Fallback محلي   │
           │ (JSON)   │  │ (Rule-based)    │
           └────┬─────┘  └────────┬────────┘
                │                 │
                └────────┬────────┘
                         ▼
                ┌──────────────────┐
                │ تنظيف + تصحيح   │
                │ sanitize()       │
                └────────┬─────────┘
                         ▼
              { priority, specialty,
                wait_time, reasoning,
                confidence, source }
```

## 🧠 موفّرو AI

### Groq (الافتراضي)

```php
define('AI_PROVIDER', 'groq');
define('AI_GROQ_MODELS', [
    'llama-3.3-70b-versatile',   // الأقوى — يُستخدم أولاً
    'llama-3.1-8b-instant',      // أسرع — fallback
    'gemma2-9b-it',              // fallback أخير
]);
```

**خاصية فريدة:** Fallback تلقائي بين الموديلات عند:
- `429` — انتهاء الكوتا
- `503` / `529` — الخدمة غير متاحة
- فشل تحليل JSON

### Gemini
```php
define('AI_PROVIDER', 'gemini');
define('AI_MODEL', 'gemini-model-name');
```

### OpenAI
```php
define('AI_PROVIDER', 'openai');
define('AI_MODEL', 'gpt-4');
```
- يستخدم `response_format: json_object` لضمان JSON صحيح

## 🎯 مستويات الأولوية

| المستوى | الوصف | وقت الانتظار | بداية البحث عن موعد |
|---|---|---|---|
| **Critical** (حرجة) | تدخل فوري مطلوب | فوري | اليوم |
| **Medium** (عاجلة) | متابعة سريعة | 1-14 يوم | اليوم التالي لآخر موعد Critical |
| **Routine** (مستقرة) | متابعة روتينية | شهر أو أكثر | اليوم التالي لآخر Critical أو Medium |

## 🔧 المحرك الاحتياطي (Local Fallback)

يعمل بدون أي API خارجي — **Rule-based scoring**:

### نظام النقاط

| المعيار | النقاط |
|---|---|
| **أعراض حرجة** (ألم صدر، فقدان وعي، شلل، نزيف، تشنجات...) | +3 لكل عرض |
| **أعراض عاجلة** (حمى شديدة، ألم بطن، دوخة، صداع مفاجئ...) | +2 لكل عرض |
| **أمراض مزمنة عالية الخطر** (قلب، سكري، ضغط) | +1 لكل مرض |
| **شدة الألم ≥ 9** | +3 |
| **شدة الألم 7-8** | +2 |
| **شدة الألم 5-6** | +1 |
| **مدة < 24 ساعة** | +2 |
| **مدة 1-3 أيام** | +1 |

### حدود التصنيف

| النقاط | الأولوية |
|---|---|
| ≥ 6 | Critical |
| 3-5 | Medium |
| 0-2 | Routine |

### تخمين التخصص (`guessSpecialty`)

يبحث في نص الأعراض عن كلمات مفتاحية لـ 8 تخصصات:

```
أعصاب ← رأس، صداع، دوخ، شلل، تنميل، صرع...
طب باطني ← قلب، صدر، تنفس، حمى، غثيان...
جراحة ← بطن، فتق، ورم، عملية...
عظام ← مفصل، كسر، ظهر، عضلات...
أطفال ← طفل، رضيع...
نساء وولادة ← حمل، ولادة، رحم...
طب طوارئ ← حادث، نزيف، تسمم، إغماء...
طب عام ← زكام، سعال، إرهاق، حكة... (افتراضي)
```

## 📅 الجدولة الذكية (`scheduleWithAI`)

### السياق المُرسل للـ AI

```
بيانات المريض:
├── الأعراض + شدة الألم + المدة
├── الأمراض المزمنة المسجّلة
└── آخر 5 سجلات طبية

بيانات الأطباء المتاحين:
├── جدول الدوام الأسبوعي (كل الشفتات)
└── المواعيد القادمة (14 يوم) مع أولوياتها
```

### خوارزمية الإزاحة التسلسلية (Cascade)

```
1. ابنِ خريطة slots كاملة
2. ابحث عن أفضل موعد للمريض الجديد
   ├── slot فارغ مناسب → لا إزاحة
   └── slot مشغول بأولوية أقل → أزِح
3. للمريض المُزاح:
   ├── ابحث في نفس اليوم أولاً
   └── إن امتلأ → اليوم التالي
   └── إن كان slot مشغول → أزِح (cascade)
4. كرر حتى لا يبقى مريض بدون موعد
```

### قيود الإزاحة
- ❌ لا تُزح أولوية مساوية أو أعلى
- ❌ لا تحجز في وقت ماضٍ
- ✅ يجوز إزاحة Routine (عادي أو ذكي)
- ✅ كل وقت يجب أن يكون ضمن دوام الطبيب

### Fallback عند فشل AI (`findBestSlot`)

```
1. جلب الأطباء حسب التخصص (أو طب عام)
2. لكل طبيب:
   ├── تحديد تاريخ بداية البحث (getSearchStartDate)
   │   ├── Critical → اليوم
   │   ├── Medium → بعد آخر Critical
   │   └── Routine → بعد آخر Critical أو Medium
   └── البحث عن أول slot فارغ (30 يوم)
3. إرجاع أول slot يُعثر عليه
```

### التحقق بعد AI

بعد استلام قرار AI، يتم:
1. التحقق أن الموعد موجود فعلاً
2. التحقق أن الوقت ضمن دوام الطبيب
3. إذا فشل التحقق → `findFirstFreeSlot()` كبديل
4. تحديث المواعيد المُزاحة في قاعدة البيانات
5. إرسال إشعارات للمرضى المتأثرين
