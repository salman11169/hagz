## نظرة عامة

**شفاء+** هو نظام إدارة عيادات طبية متكامل مبني بالذكاء الاصطناعي، مُصمم خصيصاً للبيئات الصحية الناطقة بالعربية. على عكس أنظمة الحجز التقليدية التي تعمل بمبدأ **«من يأتي أولاً يُخدَم أولاً»**، يُقدّم شفاء+ **طبقة فرز ذكية** تُصنّف المرضى حسب درجة الخطورة الطبية — لضمان عدم تأخر أي حالة حرجة خلف المراجعين الروتينيين.

يتكامل النظام مع نماذج لغوية ضخمة (LLMs) من **Groq** و**Google Gemini** و**OpenAI** لتحليل الأعراض لحظياً، وتوجيه المريض للتخصص المناسب، وجدولة المواعيد بالإزاحة التسلسلية.

### مقارنة القيمة المضافة

| النظام التقليدي | شفاء+ |
|---|---|
| من يأتي أولاً يُخدَم أولاً | جدولة حسب الأولوية الطبية |
| اختيار التخصص يدوياً | توجيه تلقائي بالذكاء الاصطناعي |
| حجز مواعيد ثابت | إزاحة تسلسلية للحالات الطارئة |
| لا يوجد تحليل أعراض | تصنيف ذكي بمعالجة اللغة الطبيعية |

## المميزات الرئيسية

### 🤖 محرك الفرز بالذكاء الاصطناعي
- **تصنيف الأعراض**: تحليل أعراض المريض باستخدام معالجة اللغة الطبيعية (NLP) وتصنيفها إلى ثلاث مستويات: **حرجة**، **عاجلة**، **مستقرة**.
- **التوجيه التخصصي**: ربط الأعراض تلقائياً بالتخصص الطبي المناسب (مثال: "ألم في الصدر يمتد لليد" ← طب القلب/الطوارئ).
- **مراعاة الأمراض المزمنة**: رفع درجة الخطورة بناءً على الحالات المزمنة المسجلة (مثال: مريض سكري يشكو من غثيان ← أولوية مرتفعة).
- **نسبة الثقة**: تقديم نسبة ثقة رقمية لكل قرار فرز.

### 🔄 نظام الإزاحة التسلسلية (Cascade Scheduling)
- **اختراق الطابور**: عند وصول حالة حرجة وجميع الأطباء مشغولون، يُعيد النظام جدولة مراجعين أقل أولوية تلقائياً.
- **خوارزمية الإزاحة**: تنفيذ إعادة جدولة متعددة المراحل مع تقليل التأثير على المواعيد القائمة.
- **المحرك الاحتياطي**: عند تعطّل خدمات الذكاء الاصطناعي، ينشط محرك محلي قائم على القواعد يحتوي على +50 كلمة مفتاحية طبية مُصنّفة.

### 👨‍⚕️ لوحات تحكم متعددة الأدوار
- **لوحة المشرف (Admin)**: إحصائيات شاملة للنظام، إدارة الأطباء والمرضى، تحليلات الأداء، وإعدادات النظام.
- **لوحة الطبيب**: قائمة مرضى اليوم مع فلترة الأولويات، تنبيهات الطوارئ، إدارة الجدول، نظام التحويلات، وتفاصيل المواعيد مع ملخصات الذكاء الاصطناعي.
- **لوحة المريض**: معالج الحجز (ذكي أو عادي)، السجل الطبي، الوصفات، الفواتير، الملخص الصحي، والإشعارات.

### 🗓️ وضعا الحجز
- **الحجز الذكي**: مسار مدعوم بالذكاء الاصطناعي يُحلّل الأعراض ويختار تلقائياً أفضل طبيب وتاريخ ووقت.
- **الحجز العادي**: المسار التقليدي حيث يختار المريض التخصص والطبيب والموعد يدوياً.

### 📋 السجلات الطبية والوصفات
- تتبع التاريخ الطبي الكامل لكل مريض.
- ملاحظات الطبيب، التشخيص، جدولة المتابعة.
- إدارة الوصفات مع تفاصيل الدواء والجرعة والتكرار والمدة.
- تتبع الفحوصات المخبرية وتسجيل الأعراض.

### 🔔 الإشعارات اللحظية
- تنبيهات طوارئ حمراء على لوحة الطبيب للحالات الحرجة.
- نظام شارات الإشعارات مع عداد غير المقروء.
- رسائل فلاش عبر معلمات الرابط (URL) للتواصل بين الصفحات.

### 🔀 نظام تحويل الأطباء
- يستطيع الأطباء تحويل المريض لاستشاري مع ملخص سريري.
- توجيه التحويلات حسب الأولوية (روتيني، عاجل، طوارئ).
- تتبع دورة حياة التحويل الكاملة (معلّق ← مقبول ← مكتمل).

## محرك الفرز الذكي (AI)

محرك الفرز الذكي (`services/TriageAI.php`) هو الميزة الجوهرية التي تُميّز شفاء+ عن أي نظام حجز تقليدي.

### آلية العمل

```
أعراض المريض ← تصنيف بالذكاء الاصطناعي ← تحديد الأولوية ← جدولة ذكية
                                                                  ↓
                                                         إزاحة تسلسلية
                                                    (عند الحاجة للحالات الحرجة)
```

### خط أنابيب التصنيف

1. **معالجة المدخلات**: تُجمع أعراض المريض، مستوى الألم (1-10)، المدة، والأمراض المزمنة من معالج الحجز.
2. **تحليل الذكاء الاصطناعي**: يُرسل طلب JSON مُهيكل إلى النموذج اللغوي يطلب:
   - `priority`: حرجة | عاجلة | مستقرة
   - `specialty`: التخصص الطبي الموصى به
   - `reasoning`: شرح قرار التصنيف
   - `confidence`: نسبة الثقة (0.0 – 1.0)
3. **الجدولة الذكية**: يستقبل الذكاء الاصطناعي المواعيد المتاحة ويُعيد الموعد الأمثل، بما في ذلك تعليمات إعادة الجدولة إن لزم.
4. **تنفيذ الإزاحة**: عند الحاجة لإعادة الجدولة، يُنقل المرضى الأقل أولوية إلى مواعيد مجاورة.

### مستويات الأولوية

| الأولوية | التسمية | معايير التفعيل | الإجراء |
|---|---|---|---|
| **حرجة (Critical)** | 🔴 حرجة | ألم ≥ 9، درجة أعراض عالية، كلمات مفتاحية قلبية/تنفسية | توجيه طوارئ، اختراق طابور، موعد فوري |
| **عاجلة (Medium)** | 🟡 عاجلة | ألم ≥ 6، أعراض متوسطة، بداية حديثة | جدولة أولوية خلال ساعات |
| **مستقرة (Routine)** | 🟢 مستقرة | ألم منخفض، أعراض مستقرة، إدارة مزمنة | جدولة عادية |

### المحرك الاحتياطي (Fallback)

عند تعذر الوصول لخدمات الذكاء الاصطناعي، ينشط **محرك محلي قائم على القواعد** يحتوي على:
- **+50 كلمة مفتاحية طبية** بالعربية والإنجليزية مُصنّفة حسب الأولوية والتخصص.
- **تسجيل نقاط مُرجّح** بناءً على شدة الأعراض، مستوى الألم، المدة، والأمراض المزمنة.
- **مطابقة الكلمات المفتاحية**: مثال: `نزيف`، `إغماء`، `ضيق تنفس` ← حالة حرجة.

### إعداد مزود الذكاء الاصطناعي

```php
// config/ai.php
'provider'  => 'groq',                    // groq | gemini | openai
'api_key'   => getenv('GROQ_API_KEY'),    // متغير بيئي
'model'     => 'llama-3.3-70b-versatile', // النموذج الافتراضي
'fallback_models' => [
    'llama-3.1-8b-instant',
    'gemma2-9b-it'
],
```

## واجهات برمجة التطبيقات (API)

جميع نقاط النهاية تُوصل عبر وحدات تحكم PHP بتوجيه مبني على الإجراء (action).

### التوثيق والمصادقة (`AuthController.php`)

| الطريقة | نقطة النهاية | الإجراء | الوصف |
|---|---|---|---|
| POST | `AuthController.php?action=login` | `login` | تسجيل دخول بالبريد وكلمة المرور |
| POST | `AuthController.php?action=register` | `register` | تسجيل مريض جديد (متعدد الخطوات) |
| POST | `AuthController.php?action=forgot_password` | `forgot_password` | إرسال رمز تحقق OTP |
| POST | `AuthController.php?action=verify_code` | `verify_code` | التحقق من الرمز المكون من 6 أرقام |
| POST | `AuthController.php?action=reset_password` | `reset_password` | تعيين كلمة مرور جديدة |

### الحجز (`BookingController.php`)

| الطريقة | النقطة | الإجراء | الوصف |
|---|---|---|---|
| GET | `?action=specializations` | `specializations` | قائمة التخصصات النشطة |
| GET | `?action=doctors&spec=...` | `doctors` | الأطباء حسب التخصص |
| GET | `?action=slots&doctor_id=...&date=...` | `slots` | المواعيد المتاحة |
| POST | `?action=triage` | `triage` | تحليل الأعراض بالذكاء الاصطناعي والجدولة |
| POST | `?action=book` | `book` | إنشاء موعد جديد |

### المريض (`PatientController.php`)

| الطريقة | النقطة | الإجراء | الوصف |
|---|---|---|---|
| GET | `?action=dashboard` | `dashboard` | الإحصائيات + المواعيد القادمة |
| GET | `?action=profile` | `profile` | ملف المريض + الأمراض المزمنة |
| POST | `?action=update_profile` | `update_profile` | تحديث بيانات الملف |
| GET | `?action=records` | `records` | تاريخ السجلات الطبية |
| GET | `?action=prescriptions` | `prescriptions` | الوصفات الفعالة |
| GET | `?action=bills` | `bills` | سجل الفواتير |
| POST | `?action=cancel_appointment` | `cancel_appointment` | إلغاء موعد |

### الطبيب (`DoctorController.php`)

| الطريقة | النقطة | الإجراء | الوصف |
|---|---|---|---|
| GET | `?action=dashboard` | `dashboard` | إحصائيات الطبيب + القائمة القادمة |
| GET | `?action=today_queue` | `today_queue` | قائمة مرضى اليوم مع الأولوية |

## التثبيت والإعداد

### المتطلبات الأساسية

- **PHP** ≥ 8.2 مع الإضافات: `pdo_mysql`، `curl`، `json`، `mbstring`
- **MariaDB** ≥ 10.4 / MySQL ≥ 8.0
- **Apache** مع تفعيل `mod_rewrite`
- **مفتاح API** للذكاء الاصطناعي (واحد على الأقل من: Groq، Gemini، أو OpenAI)

### خطوات التثبيت

1. **استنساخ المستودع**
   ```bash
   git clone https://github.com/your-repo/hagz.git
   cd hagz
   ```

2. **إعداد قاعدة البيانات**
   - إنشاء قاعدة بيانات:
     ```sql
     CREATE DATABASE hagz_clinic_ai CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
     ```
   - استيراد المخطط:
     ```bash
     mysql -u root -p hagz_clinic_ai < "hagz_clinic_ai (1).sql"
     ```

3. **إعداد اتصال قاعدة البيانات**
   - تعديل `config/database.php`:
     ```php
     $host = '127.0.0.1';
     $db   = 'hagz_clinic_ai';
     $user = 'root';
     $pass = '';
     ```

4. **إعداد مزود الذكاء الاصطناعي**
   - تعيين مفتاح API كمتغير بيئي:
     ```bash
     export GROQ_API_KEY="gsk_your_api_key_here"
     ```
   - أو تعديل `config/ai.php` مباشرة (غير مُوصى به للإنتاج).

5. **إعداد Apache**
   - توجيه DocumentRoot إلى مجلد المشروع.
   - التأكد من تفعيل `.htaccess` (`AllowOverride All`).
   - المشروع يتوقع أن يُقدَّم تحت المسار `/Hagz/` (قابل للتغيير في `.htaccess`).

6. **التشغيل**
   - الوصول عبر `http://localhost/Hagz/public/index.php`

### بيانات الدخول الافتراضية (من بذرة SQL)

| الدور | البريد الإلكتروني | كلمة المرور |
|---|---|---|
| مشرف | `admin@hagz.com` | *(راجع بذرة SQL — تجزئة bcrypt)* |
| طبيب | `abdulaziz@hagz.sa` | *(نفس التجزئة المبذورة)* |

> ⚠️ **ملاحظة**: جميع المستخدمين المبذورين يشتركون بنفس تجزئة كلمة المرور bcrypt. يجب الحصول على كلمة المرور النصية من فريق التطوير.

## الأمان والحماية

| المجال | التنفيذ |
|---|---|
| **المصادقة** | `password_hash()` مع bcrypt (الإعداد الافتراضي لـ PHP) |
| **حقن SQL** | عبارات PDO المُعدّة (Prepared Statements) في جميع وحدات التحكم |
| **حماية XSS** | `htmlspecialchars()` على جميع المخرجات المواجهة للمستخدم |
| **حماية CSRF** | غير مُنفّذ صراحةً — يعتمد على التحقق من الجلسة |
| **التحقق من المدخلات** | تحقق من جانب الخادم في `functions.php` (بريد، هاتف، تنظيف) |
| **أمان الجلسة** | انتهاء الجلسة، فحص عنوان IP ووكيل المستخدم في `session.php` |
| **مفاتيح API** | مُخزّنة في متغيرات بيئية (`getenv()`) |
| **رفع الملفات** | مقتصر على صور ملفات الأطباء مع التحقق من المسار |
| **تطبيق الصلاحيات** | حراسة على مستوى الصفحة و API على كل نقطة نهاية محمية |

### القيود المعروفة

- لا يوجد تنفيذ لرمز CSRF — اعتماد على المصادقة بالجلسة فقط.
- رمز OTP لإعادة تعيين كلمة المرور مُخزّن في `$_SESSION` ولا يُرسل فعلياً بالبريد (وضع التطوير).
- لا يوجد تحديد لمعدل محاولات تسجيل الدخول (Rate Limiting).
- لا يوجد فرض HTTPS على مستوى التطبيق (يعتمد على إعدادات الخادم).
